# 向导（Wizard）

**wizard** 是一个 bash 脚本，一步一步带一个人类走完一段手动流程——手工做很繁琐、每次重新解释给 AI 听也很繁琐的那种。它打开每个 URL，准确说出点什么、复制什么，捕获值，写进它们该去的地方（`.env`、GitHub secrets），每个阶段都确认，并显示还剩几个阶段。它可能是在配置第三方服务、跑一次一次性迁移、或把项目从一种状态搬到另一种状态。

令人愉悦的 UX 已经由 [template.sh](template.sh) 解决：逐阶段的进度、确认门、跨平台 URL 打开（包括 WSL）、隐藏式机密输入、幂等的 `.env` upsert、`gh secret`/`gh variable` 写入，以及收尾摘要。**你的工作只是框定流程并撰写它的各个阶段。** `STAGES` 标记之上的库在每个 wizard 里都一模一样；这种一致性正是要点：绝不手改它。

wizard 默认是一次性的：为一次运行而建，保存到 scratch 或 `scripts/` 路径，活干完就删。只有当用户想要一条应该留在仓库里的可重复安装路径时才提交它。

## 流程

### 1. 框定流程

理清人类必须执行的每个手动步骤，以及沿途被捕获的每个值。先读仓库，不要冷头去问：

- 安装类：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置、以及 `.github/workflows/*`（每个 `secrets.*` / `vars.*` 引用都是 wizard 必须产出的值）。
- 迁移或切换类：当前状态、目标状态、以及介于其间的不可逆动作。

然后向用户展示排好序的阶段列表和每个阶段产出的值，并确认：他们可能要加、删、重排。

**完成判据：**每个阶段按顺序有了名字，且对每个被捕获的值你知道 (a) 人类从哪里拿到它，(b) 它写到哪（`.env`、GitHub secret、两者、或哪儿都不写；有些阶段是纯动作），以及 (c) 它是机密（隐藏输入）还是公开的。

### 2. 勾勒每个阶段的路径

对每个阶段，写下人类要走的精确路径：打开哪个 URL、在那里做什么、值在哪里显示、它填进哪个变量：例如"Dashboard → Developers → API keys → Reveal test key → 复制"。在你并不真正了解当前 UI 或确切命令的地方，直说并询问用户或查文档：绝不发明可能不存在的步骤。

**完成判据：**每个阶段都能落到一个陌生人也能照做的具体指令。

### 3. 撰写 wizard

把 `template.sh` 复制到目标路径。把示例阶段替换为每步一个 `stage`，按依赖顺序排列。使用库助手：`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`。把 `TOTAL_STAGES` 设为你写的阶段数。

守住模板立下的标准：先打开 URL 再要它的值，机密一律用 `ask_secret`，每个持久化的值都 `write_env`，CI 真正需要的值才 `set_secret`，任何不可逆动作前先 `confirm`。每个 `stage` 都会清屏，只留当前步骤可见：把一个 stage 控制在一件事上，别让人类需要的东西滚出屏幕。不要碰标记之上的库。

### 4. 验证并交接

- `bash -n <script>`；有 `shellcheck` 就跑一下。
- `chmod +x <script>`。
- 不要自己端到端运行它：它会打开浏览器并阻塞在人类输入上。改为静态走查：第 1 步的每个值都被捕获并落到第 1 步所说的位置，且每个 `set_secret` 的名字与 CI 里的 `secrets.*` 引用精确对应。
- 告诉用户怎么运行。如果这是一条可重复的安装路径，提交它并从 README 链接过去，让下一个人跑脚本而不是问 AI。
