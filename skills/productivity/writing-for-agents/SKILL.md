一份关于撰写任何供 agent 消费的文档的参考：skill、`AGENTS.md` / `CLAUDE.md`、通过指针触达的文档。包装各不相同，写法则一：同样的杠杆能让每一份都变得可预测，因为 agent 每次运行走的是同一个_过程_，而不是产出同一个输出。

当你在写的文档是 skill 时，阅读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md) 了解 frontmatter、调用方式的选择和路由式 skill。

## 上下文指针

**上下文指针（context pointer）**是保存在 agent 上下文中的一条引用，它指名某份上下文之外的材料，并编码了触达它的条件。skill 的 description 是一个；`AGENTS.md` 里指名某文档的一行也是同类对象。决定 agent 何时触达材料、以及触达得多可靠的，是指针的_措辞_，而不是它的目标。一个必备目标藏在措辞无力的指针后面，就是一个方差 bug：先磨尖措辞，只有磨尖失败时才把材料内联进来。

一个指针做两件事：说明材料是什么，并列出应当触发触达的**分支**（分支是文档处理的一种独立情形，因此不同运行会走不同的路径）。常驻加载的指针，每个词每一轮都在花费成本，所以它比正文更配得上狠狠修剪：

- **把引导词放在最前面**：指针正是它发挥触发作用的地方。
- **每个分支一个触发词。** 给同一个分支换名字的同义词，等于把一个分支写了两遍；合并它们，只保留真正不同的分支。
- **删掉正文已承载的标识信息。**

## 两种负载

你添加的每一份文档和指针，都要花费两种预算之一：

- **上下文负载（context load）**是常驻加载材料对 agent 窗口的代价：`AGENTS.md` 里的一行、skill 的 description、任何每轮都待在上下文里的东西，无论是否触发都在消耗 token 和注意力。
- **认知负载（cognitive load）**是对人的代价：存在哪些文档、何时该用哪份。人就是索引。这不是要最小化的成本：它是人类能动性的代价；在人类判断要紧的地方花它，在不要紧的地方去掉它。

只能通过指针触达的材料，以指针自身那一行为代价躲开了上下文负载；完全没有指针的材料，则全靠认知负载驮着。

## 信息层级

文档由两类内容构成：**步骤（steps）**（agent 依序执行的动作）和**参考（reference）**（按需查阅的定义、规则、事实）。两者可自由混合：全是步骤（一份食谱）、全是参考（一场 review 的规则、本 skill）、或两者兼有。核心决策是每一块内容落在**信息层级（information hierarchy）**的哪一层——一架按 agent 对材料的需求有多紧迫来排位的梯子：

1. **文件内步骤（in-file step）**是主层级：agent 按顺序所做的事。
2. **文件内参考（in-file reference）**按需查阅。它常常是一个合理的扁平同级集合（一场 review 的所有规则站在同一级上），这是良好的安排，不是坏味道。
3. **外置参考（disclosed reference）**被推到单独的文件中，通过上下文指针触达，只在指针触发时加载。范围从同文件夹的兄弟文件，一直到可以放在任何地方、任何文档都能指向的完全外部参考。

下推得太少，顶部就会膨胀；下推得太多，你会藏起 agent 真正需要的材料。这个张力就是决策的全部。

**渐进式披露（progressive disclosure）**就是沿梯子下移（移出主文件、藏到指针后面），好让顶部保持可读。它首先不是 token 优化：它是保护层级结构的方式。分支是检验披露与否的最干净测试：每个分支都需要的就内联，只有部分分支会触达的就推到指针后面。当文档含有步骤时，本该外置的文件内参考会把步骤埋起来，让「注意到步骤」变成抛硬币：这不仅是可读性杠杆，更是方差杠杆。

**就近聚合（co-location）**是文件内的对应操作：梯子决定一块内容_落多深_，就近聚合则决定它落定后_旁边是什么_。把一个概念的定义、规则和注意事项放在同一个标题下，而不是四处散落，这样读其中一部分就会把邻居一并带出来。检验标准：文档读起来应当像是为 agent 写的正式文档。聚合的材料读起来是那样；散落的材料不是。（它与重复不同：重复是把同一个意思在两处写两遍；散落是把一个意思打碎撒到多处。）

**蔓延（sprawl）**是这里的失败模式：文档单纯地太长了，哪怕每一行都有效且唯一。注意力被冗余部分摊薄，每多一行就多一行要维持相关性的行。解药是那架梯子：把参考披露到指针后面，并按分支或序列拆分，让每条路径只携带它需要的东西。

## 步骤与完成判据

每个步骤都以一条**完成判据**收尾——告诉 agent 工作已完成的条件。两个属性让它成为杠杆：

- **清晰度**：agent 能否分辨完成与未完成？模糊的边界（「达成了理解」）会招来**过早完成**：在真正完成之前就结束步骤，注意力滑向_完成本身_。仍显现在前方的后续步骤（**完成后续步骤**）提供拉力，判据的清晰度就是阻力。按顺序防御：**先把边界磨利**（局部且便宜）；只有当它不可再磨_且_你确实观察到赶工时，才通过拆分序列把后面的步骤藏起来。藏只在真正的上下文边界（一次交接或一次子代理派发）对面才有效；内联调用会把后续步骤留在上下文里，什么也清不掉。
- **要求度**：它要求了多少。「每个被修改的 model 都有着落」会逼出彻底的工作，而「产出一份变更清单」不会。要求度驱动**跑腿工作（legwork）**（agent 在任务内部做的挖掘，潜伏在措辞里而非写成独立步骤），而且它不限于步骤：「每条规则都已应用」对一整块扁平参考的约束力，就像「每步都已完成」对序列的约束力一样——这正是纯参考文档也能携带穷尽性标准的方式。

最强的判据既可检验又穷尽。

## 何时拆分

把一份文档拆成两份会花费两种负载之一，所以只在拆分真正值回成本时才拆：

- **按序列拆**：当后续步骤诱使 agent 赶完眼前这步时，拆开这串步骤。让它们不进入视野，能驱动在当前任务上做更多跑腿工作。小心反方向：合并序列会让每一步的后续步骤暴露在紧随其后的内容面前，招来过早完成。
- **按调用方式拆**，skill 专属：见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 引导词

**引导词（leading word）**是已经活在模型预训练中的一个紧凑概念，agent 在执行文档时就用它来思考（_lesson_、_fog of war_、_tracer bullets_）。它作为 token 而非句子被重复，逐渐积累出一个分布式定义，并通过调用模型已有的先验，用最少的 token 锚定一整片行为区域。自己造词也行，只要定义清晰，但生造的词调动不了先验：预训练词免费给你的，你得用定义 token 去付账；优先选用现成的词。

它锚定两次。在正文中锚定_执行_：每当这个词出现，agent 就伸手去拿同一个行为；在扁平参考内部，它把注意力聚焦到要找的一类东西上。在指针中锚定_调用_：当同一个词同时活在你的 prompt、你的文档和你的代码库里，agent 会把这种共享语言与材料关联起来，更可靠地触达它。

猎取用引导词做重构的机会。在三个位置被逐字铺开的三件套，一个花掉整句话去比划单一想法的指针。每一段都在哀求塌缩成一个 token：

- "fast, deterministic, low-overhead" → _tight_（一个 _tight_ 的循环）。
- "a loop you believe in" → _red_，把模糊的门变成可观察的二值状态（循环对这个 bug 变 _red_，或者没有）。

你赢两次：token 更少，而且给 agent 一个更锋利的挂钩来挂它的思路。假设每份文档都藏着能被引导词退役的复述。去找出来。

**否定式（negation）**是这支杠杆旁边的失败模式：用禁止来掌舵，会把被禁止的行为拖进上下文，让它_更_容易浮现，而不是更少。_别想大象_，结果满脑子都是大象；否定词是个弱修饰符，会被强激活的概念碾过去，于是这条禁令读起来一半像是在指示去做那件事。用**肯定式**下指令：陈述目标行为（「写单行注释」），让被禁的那个根本不被说出。禁令只有在无法用肯定句表述的硬性护栏场景才配占一席；即便那时，也要配上肯定的目标，好让注意力落在该做什么上。

## 修剪

- 让每个意思只有一个**单一事实来源**：一个权威位置，这样改变行为只需改一处。**重复（duplication）**（同一意思出现在多于一个地方）消耗维护成本和 token，还会把一个意思在梯子上的显著度抬高到超过它的真实排位。（它与引导词恰好是无意间的反面：引导词故意重复的是 token，从来不是意思。）
- **环境**也是事实来源（`package.json` 脚本、配置文件、目录布局、`--help` 输出），复述环境的文档是一份**缓存**：一次查询的副本，只有当查询很贵时才配得上它的负载。缓存 agent 看一眼找不到的东西：没写下来的约定、某个选择背后的原因、任何配置都不会坦白的坑。把一文件、一命令级别的查询留给环境，在那里它们不会过期。
- 逐行检查**相关性**：它还与文档的职责相关吗？一行内容会因从未与任务相关（纯粹的解释，或一个本该外置的分支）而失去相关性，也会随着它所描述的行为或世界的变化而过时。越短的文档越容易保持相关。没有修剪纪律，默认结局是**沉积（sediment）**：因为添加感觉安全、删除感觉冒险而层层沉降的过时地层，直到你必须一路钻透它们才能找到还活着的东西。
- 逐句猎杀**空转指令（no-op）**：模型默认就会照做的指令，花了负载却什么也没说。检验标准（相对默认行为，它改变行为了吗？）是相对于模型的，不是相对于读者的：两个人对空转与否的分歧其实是对默认行为的分歧，靠运行文档解决，不靠争论。一句话不达标时，删掉整句，而不是从里面修剪字词。这个检验也给引导词打分：弱到赢不过默认行为的词（agent 本来就挺 thorough 时说 _be thorough_）就是空转，解法是换更强的词（_relentless_），而不是换别的技巧。
