# RAG 生产检查清单（15 章汇总）

> 依据《生产级 RAG 系统——从架构到 Python 实现》各章「生产检查项」整理。
>
> **用法**：上线前全表过一遍；任何检索层变更只过受影响章节 + 第 12/14 章门禁。逐项打勾，
> 打不了勾的项写明原因与缓解措施——没有书面答案的检查项等于未通过。

## 01 需求

- [ ] 需求八问（文档类型规模 / 查询分布 / 精确性 / 延迟吞吐 / 权限租户 / 更新频率 / 预算 / 合规）全部有书面答案
- [ ] 收集了 10-20 条真实查询样例并完成人工分类
- [ ] 每类查询（语义/精确/结构化/时序/多文档/多跳）有明确路由通道
- [ ] 精确性等级明确（聊天参考 vs 引用级），并据此确定了引用验证深度

## 02 数据模型

- [ ] 事实层（System of Record）与检索层分离：向量索引是派生物
- [ ] DocumentVersion 不可变，以 content hash 去重
- [ ] ACL 只存事实层，索引 metadata 仅作查询过滤副本
- [ ] 文档删除/更新能传播到索引，旧版本不再可被检索
- [ ] as_of 时序语义已定义并通过测试
- [ ] 全量重建索引演练通过，重建期间检索可用

## 03 摄取

- [ ] 摄取幂等：重跑不产生重复 chunk
- [ ] 增量索引只处理 content hash 变化的版本
- [ ] 摄取失败有重试与死信队列，失败可见
- [ ] 语料来源有 allowlist，新增来源需审批
- [ ] 不同数据类型（代码/多模态）有对应摄取路径

## 04 Chunking

- [ ] 策略由真实语料扫描决定（`chunking_optimizer.py`），而非拍脑袋数值
- [ ] 块边界经人工抽样核对（至少看过 2-3 个样本块）
- [ ] parent-child（小块检索、大块返回）决策有记录
- [ ] chunk 携带 section_path 或上下文头，检索结果可定位回原文

## 05 Embedding

- [ ] 按档位选型，具体模型名与价格带"用前核实"注记及截至日期
- [ ] 维度 × 规模的存储与内存预算已核算
- [ ] 多语言/代码等特殊语料选了对应档位

## 06 索引与向量库

- [ ] 选型标准（托管 vs 自托管、规模、过滤能力、现有 Postgres）记录在案
- [ ] metadata 过滤字段至少含 tenant 与 version
- [ ] 索引有版本号，与事实层可对账
- [ ] 容量规划覆盖一年内增长

## 07 检索

- [ ] 检索通道覆盖需求八问里的全部查询类型
- [ ] 所有查询按 principal 强制过滤，无"检索后过滤"路径
- [ ] 空结果有兜底策略（拒答/转人工/降级通道）
- [ ] 检索延迟 P95 达标

## 08 重排

- [ ] 重排带来的质量收益有评测数字支撑（A/B 对比）
- [ ] 重排延迟在预算内
- [ ] 重排模型失效时有降级路径（跳过重排直接返回）

## 09 上下文构建

- [ ] 上下文有 token 预算与超预算时的优先级裁剪规则
- [ ] 送入 prompt 的上下文有去重
- [ ] 多来源拼装顺序稳定可复现

## 10 生成

- [ ] 检索内容在 prompt 中以明确数据区包裹，指令与数据分离
- [ ] 系统提示声明数据区内容不作为指令执行
- [ ] 无法回答时的拒答话术已定义
- [ ] 输出格式（引用标记、结构化）有明确规范

## 11 引用

- [ ] 答案拆分为原子 claim，每条 claim 独立挂引用
- [ ] 三层验证（存在性/蕴含/权限）全部上线
- [ ] Citation Resolver 在查询时按 principal 重新授权
- [ ] 引用钉死 version_id，源文档更新不漂移
- [ ] 引用覆盖率有门禁阈值，低于阈值降级或人工审核

## 12 评测

- [ ] 评测集按 query type / 语言 / 租户分片，各分片有独立阈值
- [ ] ground truth 带 as_of 与 principal 字段
- [ ] 评测跑在 CI 中，跌破阈值阻断发布
- [ ] 失败案例进入评测集沉淀（评测集持续生长）

## 13 安全

- [ ] 越权回归测试集全绿并纳入 CI
- [ ] prompt injection 演练：注入内容不改变系统行为
- [ ] 投毒防线（来源 allowlist、抽样人审、来源命中率监控）就位
- [ ] 权限收回的传播路径（ACL → 索引 → 缓存答案）经过验证
- [ ] 数据驻留与审计留痕满足合规八问的答案

## 14 可观测

- [ ] 分片面板上线，每个分片有基线、阈值、责任人
- [ ] 引用覆盖率、越权拦截等安全信号有独立告警
- [ ] 检索层变更走 Shadow / Canary，有分片对比记录
- [ ] 每查询成本与 token 用量可见

## 15 部署

- [ ] 索引版本管理与不停机重建方案已落地
- [ ] 回滚预案演练过（一次真实回滚或演练记录）
- [ ] 容量与月度成本上限有告警
- [ ] 事实层与索引层的灾备一致（恢复顺序：先事实层，后重建索引）
