# 数据类型处理

## 概述
当源材料不是普通散文，或不同数据类型需要不同的解析、元数据、分块和检索策略时，使用这个父级 skill。

## 问题陈述
代码、API、表格、图片、图表和混合媒体在按普通文本处理时会丢失重要含义。RAG 系统需要针对数据的处理方式来保留符号、结构和视觉上下文。

## 关键概念
- **代码结构**：保留符号、路径、API 和示例。
- **多模态提取**：把图片、图表和表格转换成可检索的表示。
- **元数据对齐**：让各模态之间的来源引用保持一致。
- **专项检索**：让查询类型匹配到正确的内容表示。

## 实施指南

### 第 1 步：对源内容分类
判断语料是代码为主、图片为主、表格为主，还是混合型。

### 第 2 步：保留原生结构
使用能保留符号、题注、标题、页码和来源位置的解析器和元数据。

### 第 3 步：选择检索表示
按需索引文本、摘要、题注、代码符号、表结构或多模态 embedding。

## 何时使用本 skill
- 为技术文档或代码仓库构建 RAG
- 索引 PDF、图表、截图或表格
- 在答案中组合文本与非文本证据

## 何时不要使用本 skill
- 语料是简单散文
- 主要问题是向量数据库运维
- 主要问题是生产环境延迟

- 符号、题注、表格和来源引用检索准确
- 代码或视觉类问题的幻觉更少
- 能清晰追溯回原始产物
