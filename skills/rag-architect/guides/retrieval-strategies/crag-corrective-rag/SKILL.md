## 概述
纠正式 RAG（Corrective RAG，CRAG）在标准检索之上增加了对文档相关性的动态评估，并在需要时纠正检索过程。它将本地知识库与 web 搜索结合，用相关性评分决定是使用检索到的文档、用 web 结果补充，还是完全依赖外部来源。

## 问题陈述
传统 RAG 系统在检索信息不足时存在局限：
- **检索不相关**：检索到的文档可能无法充分回答查询
- **信息过时**：本地知识库可能包含陈旧信息
- **没有质量评估**：缺少评估检索质量的机制
- **来源不灵活**：无法补充或替换较差的本地检索
- **流程静态**：不论查询特征如何都用同一种检索方式

## 核心概念
- **检索评估**：对文档相关性评分以判断质量
- **动态纠正**：根据评估结果调整检索策略
- **web 搜索补充**：本地检索不足时使用 web 搜索
- **知识精炼**：从文档中提取关键信息
- **来源选择**：根据质量在本地与外部知识之间选择

## 实施指南

### 第 1 步：实现检索评估
对每个检索到的文档针对查询的相关性评分。

**原因**：相关性评估为检索质量提供量化度量，使纠正策略的决策有据可依。

用 LLM 按文档对查询的回答程度，为每个检索到的文档打 0 到 1 的分。

### 第 2 步：实现决策逻辑
根据相关性评分确定纠正策略。

**原因**：不同相关性水平需要不同处理——高相关性直接用本地内容，低相关性触发 web 搜索，模糊情形两者结合。

- 高相关（>0.7）：直接使用本地检索结果
- 低相关（<0.3）：依赖 web 搜索
- 模糊（0.3-0.7）：本地与 web 结合

### 第 3 步：实现面向 web 搜索的查询改写
在需要外部知识时，为 web 搜索优化查询。

**原因**：web 搜索引擎对格式规范的查询响应更好。改写能改善 web 搜索结果。

在保持原始意图的前提下，将查询改写得更适合 web 搜索引擎。

### 第 4 步：实现知识精炼
从文档中提取关键信息供回答生成使用。

**原因**：原始文档可能包含过多细节。精炼提取最相关的信息，让回答生成更高效。

从文档中提取要点或关键信息，聚焦最相关的内容。

### 第 5 步：实现 web 搜索集成
在需要时获取并处理 web 搜索结果。

**原因**：web 搜索提供最新信息，可以补充或替换不足的本地检索。

集成 web 搜索 API（如 DuckDuckGo、Bing），在本地检索不足时获取外部信息。

### 第 6 步：实现回答生成
根据纠正策略使用合适的知识来源生成回答。

**原因**：回答生成器必须能处理不同知识来源——本地文档、web 结果或混合信息——并给出恰当的出处归属。

根据纠正策略生成回答：使用本地内容、web 结果或混合来源。

### 第 7 步：构建完整的 CRAG 管线
将所有组件组合成一个内聚的纠正式系统。

**原因**：包含评估、决策逻辑、web 搜索和回答生成的完整管线，提供了一个能适应信息质量的健壮检索系统。

实现模式可参考 [CRAG 论文](https://arxiv.org/abs/2401.15884)、[LangChain tools 文档](https://docs.langchain.com/oss/python/langchain/tools)，以及相关概念的 [Self-RAG 论文](https://arxiv.org/abs/2310.11511)。

## 何时使用本 skill
- 构建信息质量差异显著的 RAG 系统
- 本地知识可能过时或不完整
- 要求高准确率和最新信息的应用
- web 搜索可作为兜底来源
- 信息快速变化的领域（新闻、科技、金融）

## 何时不使用本 skill
- 没有 web 搜索访问权限的系统
- 本地知识全面且最新
- 延迟敏感的应用（web 搜索带来延迟波动）
- 要求离线运行
- 外部来源不可靠或受限制的领域

## 指标与成功标准
- **相关性评估**：文档相关性评分准确
- **纠正有效性**：动态纠正确实提升了回答质量
- **web 搜索质量**：web 搜索结果相关且可靠
- **回答准确率**：相比基线的事实准确率更高
- **延迟可接受性**：web 搜索的开销在用例中仍可接受
